# 考古版藍圖：蘿讀（網頁手感原型）

> 考古版。整個專案只有一支 `index.html`（391 行），所以沒有另外產互動流程圖，用文字畫。

## 流程

```
打開 app
  └─ 主畫面
       ├─ 沒有書 → 打書名 → 種下去 → 主畫面（有書）
       ├─ 按書名膠囊 → 書架 ─┬─ 點一本 → 切換 → 主畫面
       │                     └─ 打書名（＋拍封面）→ 種下去 → 主畫面
       ├─ 選訊號（第 3 次後才有）
       ├─ 念完了 → 記一筆 → 蘿蔔長一點 → 主畫面（顯示完成語）
       └─ 可以拔了 → 往上拖 ─┬─ 拖過 55% → 拔起來 → 進「拔起來的」那排
                             └─ 沒過 → 彈回去
  ← 左滑：蘿蔔田（還在土裡／拔起來的／這週）── 點一格 → 切換 → 主畫面
  → 右滑：設定（名字／五個字／匯出／匯入／示範資料／清空）
```

## 資料長什麼樣

- 書：編號、書名、封面小圖、有沒有拔起來、什麼時候拔的
- 念的紀錄：哪本書、什麼時候、選了哪些訊號
- 現在選的是哪本
- 她的名字

所有畫面上的數字（次數、葉子、這週）都是從「念的紀錄」當場算出來的，沒有另外存。這點對重寫是好事，原生版只要把這四樣存好，其他照算就會一樣。

## 標註

⚠️ 危險方塊（會掉資料）

- 「載入示範資料」一按就蓋掉全部真實紀錄，沒有確認。這是整支原型裡最容易出事的一顆按鈕。
- 「匯入備份」一樣直接蓋掉，沒有確認，也不檢查檔案內容對不對。
- 「清掉全部資料」有按兩次的保護。
- 「念完了」按錯沒辦法收回。一筆紀錄只是多一片葉子，損失小，但累積的次數會影響什麼時候冒芽、提示給哪個字。
- 沒有碰錢，沒有連網，沒有寄東西給任何人。

原生版會新增的危險方塊（原型沒有）

- 睡前提醒要跟 iPhone 要通知權限。
- 拍封面要跟 iPhone 要相機或相簿權限。
- 資料改存在 app 裡。刪掉 app，資料就沒了，跟原型一樣，除非另外做 iCloud。

🔁 重複疑點

- 封面那一小塊（有圖顯示圖、沒圖顯示第一個字）在主畫面和書架各寫了一次。
- 「打書名 → 種下去」在開場畫面和書架各寫了一次。
- 規模很小，重寫時自然會合成一個。

🎨 風格漂移

- 沒有。一支檔案，一個人的寫法，從頭到尾一致。

🕳️ 我沒把握的部分

- 念 0 到 2 次時點種子會不會抖。程式有寫要抖，但我看它找種子的方式，很可能找不到，所以大概不會動。要實機點一下才知道。
- 拔蘿蔔的手感。程式寫的是手指移動多少、蘿蔔就跟著上來九成，放手用 0.22 秒彈回。這在手機上順不順、會不會跟左右滑頁搶手勢，我沒摸過，判斷不了。
- 封面照片存在瀏覽器裡的容量上限。書加到幾十本、每本都有封面時會不會存不進去，程式沒有處理，存失敗也不會提示。
- 「這週」裡不好的訊號是從頭累積算的，好訊號是只看這 7 天。這是故意的還是寫的時候沒注意，程式裡看不出來。
- 完成語的輪替順序是照次數算出來的固定順序，同一本書連續幾次會不會剛好撞到同一句，我沒有逐一算過。
